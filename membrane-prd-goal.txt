Task: Produce a SPARC-structured PRD skeleton for an adversarial robustness evaluation of an edge-first agent protection architecture. This is a documentation drafting task. Expand the supplied constraints into a structured PRD. Do NOT redecide architectural questions — they are locked below.

# LOCKED DECISIONS (treat as given — do not modify, re-derive, or second-guess)

## Unit under test
A two-part deterministic host-level membrane running inside a browser-contained agent shell:
- Ingress path: host fetches raw content → MiniLM-L6-v2 embedding → HNSW lookup against a locally persisted signature store seeded with 809 attack vectors → returns either sanitized content or a synthetic error to the agent. The LLM never sees raw chaotic input.
- Egress path: intercepts agent-issued consequential actions (tool calls, memory writes, outgoing messages, structured submissions). Runs a per-tool argument contract check plus an HNSW anomaly score against the same signature store. Decides allow / block / quarantine.
- Explicitly excluded: no LLM in the decision loop. No Surgeon call. No Gemini or Claude API call inside the membrane itself.

## Evaluation modes (fixed)
- Mode 1: no membrane, baseline LLM agent
- Mode 2: ingress host-memory lookup + egress consequence gate (the thesis)
- Mode 3: Mode 2 plus plain-text output gating on all assistant utterances (the control)

## Task corpus shape (fixed)
Four buckets, approximately 80 tasks each, about 320 total:
- Benign workflows (ordinary user prompts)
- Direct adversarial prompts (known prompt-manipulation attack families, sourced from public corpora)
- Indirect adversarial content (manipulation payloads embedded in quoted documents, webpages, emails)
- Borderline items (creative, speculative, weakly grounded but harmless)
Each task carries a pre-assigned gold label from the set {safe_allow, unsafe_block, quarantine_ok, allow_ok}.

## Primary metrics (fixed)
Attack Success Rate, False Positive Rate, Containment Rate, Latency (p50 and p95), Review Burden, Explanation Quality.

## Decisions the swarm must NOT make
- Do not propose new unit-under-test definitions
- Do not pick numeric success thresholds (author will commit those separately before the run)
- Do not generate adversarial task content
- Do not introduce an LLM into the membrane decision path
- Do not recommend replacing HNSW with an LLM judge
